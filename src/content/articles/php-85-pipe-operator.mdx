    |> array_unique(...)
    |> array_values(...);`;

Data transformation pipelines are common across backend PHP code—normalizing request payloads, sanitizing slugs, filtering collections, or formatting strings. Historically, PHP offered two imperfect styles for writing chained transformations when working with standalone functions:

1. **Nested calls**, which must be read inside-out from right to left.
2. **Temporary variables**, which add visual noise when each intermediate step has no meaningful domain name.

PHP 8.5 introduces the **pipe operator (`|>`)**, enabling left-to-right function composition where the value on the left is passed as the single argument to the callable on the right.

<Callout type="compatibility" title="PHP 8.5 Language Feature">
  The pipe operator (`|>`) requires **PHP 8.5 or later**. All companion examples in this guide were verified against **PHP 8.5.12** with no extra extensions required.
</Callout>

## Pairing `|>` with First-Class Callables

Introduced in PHP 8.1, first-class callable syntax (`strlen(...)`, `trim(...)`) produces a `Closure` from any function or method. Together with `|>`, single-argument standard library functions compose cleanly without wrapper closures:

```php title="examples/php-8-5/pipe-operator/src/Slugger.php" php="8.5" showLineNumbers highlight={8-11} caption="Chaining first-class callables and closures in a single left-to-right pipeline."
<?php

declare(strict_types=1);

function normalizeSlug(string $title): string
{
    return $title
        |> trim(...)
        |> strtolower(...)
        |> (static fn (string $value): string => preg_replace('/[^a-z0-9]+/', '-', $value) ?? '')
        |> (static fn (string $value): string => trim($value, '-'));
}
```

## Practical Payload Sanitization Pipeline

In controller boundaries, form handlers, and webhook consumers, multiple independent input fields often share small single-argument sanitizers. Composing static helper callables with `|>` keeps normalization declarative and easy to scan:

```php title="examples/php-8-5/pipe-operator/src/PayloadSanitizer.php" php="8.5" showLineNumbers highlight={15-24} caption="Combining built-in PHP functions with domain-specific first-class callables in a request sanitizer."
<?php

declare(strict_types=1);

namespace KhorshedPro\Examples\Php85\PipeOperator;

final class PayloadSanitizer
{
    /**
     * @param array{email?: string, tags?: string, title?: string} $payload
     * @return array{email: string, slug: string, tags: list<string>}
     */
    public static function sanitize(array $payload): array
    {
        $email = ($payload['email'] ?? '')
            |> trim(...)
            |> strtolower(...);

        $slug = ($payload['title'] ?? '')
            |> Slugger::normalize(...);

        $tags = ($payload['tags'] ?? '')
            |> TagNormalizer::normalizePiped(...);

        return [
            'email' => $email,
            'slug' => $slug,
            'tags' => $tags,
        ];
    }
}
```

## Precedence and Execution Semantics

When writing piped expressions in PHP 8.5, keep three evaluation rules in mind:

- **Left-associative flow:** A chain `$a |> $f1 |> $f2` evaluates `$a` first, passes its result as the sole argument to `$f1`, and passes that return value to `$f2`.
- **Single-argument callable requirement:** The right-hand operand must evaluate to a callable expecting one value (or accept the piped value as its first parameter when remaining parameters are optional). Callables requiring by-reference parameters are not compatible with arbitrary piped r-values.
- **Parenthesize arrow functions and closures:** Wrapping inline closures and `fn (...) => ...` expressions in parentheses prevents operator-precedence surprises when chaining subsequent `|>` steps.

<Callout type="tip" title="Parenthesize Arrow Functions Inside Pipe Chains">
  Because `fn (...) => ...` has looser precedence boundaries around subsequent operators, always wrap inline arrow functions in parentheses—`(fn (string $v) => ...)`—before piping into the next step.
</Callout>

<Callout type="performance" title="Readability First, Not Magical Speedups">
  The pipe operator (`|>`) is primarily a readability and composition improvement over deeply nested function calls or throwaway variables. Each step still performs a normal PHP callable invocation, so avoid treating `|>` as an optimization mechanism on its own.
</Callout>

## When Not to Use Pipes

Pipes shine for linear transformations on values, strings, arrays, and DTOs. Avoid forcing `|>` into code that:

- Requires branching control flow mid-pipeline (a readable `if` block or `match` expression is clearer).
- Performs non-linear side effects or database transactions where explicit intermediate state aids debugging.
- Already uses a clean fluent object builder where method chaining provides better domain naming.
