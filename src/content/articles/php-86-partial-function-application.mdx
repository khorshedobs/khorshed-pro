## Introduction

In PHP 8.5, the pipe operator (`|>`) made single-argument transformation pipelines readable from top to bottom. However, many built-in PHP functions take two or more parameters—and the value flowing through the pipe is not always the only parameter (`array_map`, `implode`, `str_replace`, `preg_replace`).

Without partial function application, developers must wrap those calls in boilerplate closures (`static fn (string $s): string => ...`) solely to bind configuration arguments in advance.

## The Problem: Closure Ceremony Around Multi-Argument Functions

Consider normalizing text inside a PHP 8.5 pipe chain when replacing spaces with hyphens via `str_replace()`:

```php title="Closure boilerplate in PHP 8.5" php="8.5" showLineNumbers
<?php

declare(strict_types=1);

$slug = '  Modern PHP Mastery  '
    |> trim(...)
    |> strtolower(...)
    |> (static fn (string $value): string => str_replace(' ', '-', $value));
```

Even though `' '` and `'-'` are known up front, PHP 8.5 requires allocating an explicit wrapper closure just to adapt `str_replace()`'s 3-parameter signature to accept a single piped argument.

## Key Language Concepts in `partial_function_application_v2`

1. **Positional (`?`) vs. variadic (`...`) placeholders:** Single open argument slots vs. forwarding remaining trailing arguments.
2. **Deferred execution & evaluation order:** Arguments supplied when constructing the partial callable are captured immediately; execution waits until the remaining open placeholders are supplied.
3. **Named arguments & type preservation:** Bound parameters and remaining open slots preserve parameter and return types from the underlying function signature.

## Where Partial Function Application Fits Best

- **Array callbacks:** Creating reusable single-argument predicates for `array_filter()` and mappers for `array_map()`.
- **Pipe pipelines (`|>`):** Adapting standard library helpers cleanly inside linear data transformation chains.
- **Validation & middleware adapters:** Specializing generic helpers into domain-specific callbacks without duplicate wrapper functions.
