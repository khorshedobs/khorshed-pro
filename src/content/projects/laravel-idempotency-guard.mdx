## Overview

Idempotency is critical whenever state-changing operations cannot safely run twice. This architectural design enforces strict single-execution semantics behind standard HTTP `Idempotency-Key` headers.

## Storage Schema

```sql title="database/migrations/idempotency_keys.sql"
CREATE TABLE idempotency_keys (
    id BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
    idempotency_key VARCHAR(128) NOT NULL UNIQUE,
    request_hash CHAR(64) NOT NULL,
    response_status SMALLINT UNSIGNED NULL,
    response_body MEDIUMTEXT NULL,
    expires_at TIMESTAMP NOT NULL
);
```

## Request Lifecycle

Incoming requests compute a normalized SHA-256 digest of the method, route, and body; acquire an atomic lock on the key; execute the controller action once; and persist the serialized response for deterministic replay within the retention window.
